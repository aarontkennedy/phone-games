# Phone Games

Offline PWA of personal games (no server, no ads, no accounts). Vite + TypeScript, no framework.

## Standards (read before changing anything)

- docs/TESTING.md: 95% coverage on every metric, enforced. Every game also has a `simulate.test.ts` that plays many whole games. Never lower thresholds. Pure `logic.ts` + thin `index.ts` per game; inject `rng`; fake timers.
- docs/DESIGN.md: use tokens and shared components in src/style.css and src/core/ui.ts; light and dark; 44px targets; 26px min grid cells; 18px min text; contrast tests for every text color pair.
- **Flat design (required):** a minimalist style that uses two-dimensional (2D) shapes, solid colors and clean lines, with zero realistic textures, shadows or gradients. It contrasts directly with realistic styles. In practice:
  - No gradients, `box-shadow`, `text-shadow`, `filter`, `backdrop-filter`, bevels, glows, 3D effects or `url()` textures.
  - Icons are inline SVG with solid fills (src/games/icons.ts). The app icon is generated by scripts/make-icons.mjs.
  - No emoji anywhere, because they aren't flat. Board symbols (like the Mines flag) are inline SVG with `role="img"` and an `aria-label`, colored from CSS tokens, at 3:1 or better against their square.
  - Enforced by src/design.test.ts, src/games/index.test.ts and scripts/no-emoji.test.mjs. Details are in docs/DESIGN.md.
- **Readable without reading glasses (required):** the player needs reading glasses for small text. All text is at least 18px, and body text is 20px. Use the `--text-*` tokens. Never hard-code a `font-size`, and never shrink text to make something fit: wrap it, shorten it, or simplify the layout. Board numbers must be at least 18px on a 390px-wide phone. Enforced by src/design.test.ts and the E2E `expectReadableText()` helper. Details are in docs/DESIGN.md.
- docs/SECURITY.md: check dependencies every few weeks (Dependabot opens a monthly pull request; `npm run deps` checks by hand). Fix advisories in shipped code at once, high or critical in build tools within days. Never `npm audit fix --force` blindly; update one major version at a time and run `npm run check`.
- docs/LEGAL.md: generic game names only (e.g. "Mines", not "Minesweeper"); permissive licenses only; no copied code or assets; shipped third-party code listed in public/THIRD_PARTY_NOTICES.txt.

## Commands

- `npm test`: vitest with coverage thresholds
- `npm run test:e2e`: Playwright, iPhone (WebKit) and Android (Chromium) projects, including offline
- `npm run test:sim`: simulation tests (many whole games per game, no coverage)
- `npm run licenses`: dependency license allowlist
- `npm run deps`: outdated packages and security advisories
- `npm run check`: all of the above plus tsc

## Notes

- In a sandboxed session, npm network installs can fail. Ask the user to run `npm install` themselves.
- Each game is lazy-loaded from src/games/index.ts and must implement `mount(container) => cleanup`.
- Game screens must use the standard layout, in this order: `.screen` > `.stats`, `.board-frame`, optional `.recent` (recent moves, docs/DESIGN.md "Recent moves"), `.status-line`, `.controls` (stats on top, buttons at the bottom for the thumb; board on the left and side bar on the right when sideways). It's what makes the landscape side bar work (docs/DESIGN.md, "Landscape"); check new games with `e2e/landscape.spec.ts`.
- Rarely changed choices (computer level, difficulty) go in Settings behind the gear, not on the game screen: end the template with `settingsHtml(...)` from src/core/ui.ts (docs/DESIGN.md, "Settings").
- Every game needs a `category` (its home screen group: src/core/game.ts `CATEGORIES`; games are A to Z within a group, under a Most played row) and `howToPlay` rules in src/games/index.ts, written for a first-time player (docs/DESIGN.md, "How to play"). They open only from the Rules button, never by themselves.
- Card games use the shared card model and drawings (src/core/cards.ts, src/core/card-view.ts, and src/core/tricks.ts for trick-taking) and follow docs/DESIGN.md, "Playing cards".
- The About page (src/about.ts, `#/about`) must match LICENSE and public/THIRD_PARTY_NOTICES.txt (docs/LEGAL.md).
- Crashes and feedback: src/report.ts shows a "something went wrong" banner with an Email a report link, and About has Email feedback. Email only, opened in the player's own app; never add automatic reporting (docs/LEGAL.md, "Privacy").
